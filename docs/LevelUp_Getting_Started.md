## 3. Docker — What It Does Here and Why

**Short answer:** Docker runs your PostgreSQL database. That is its only job during development. You do not run Angular or Spring Boot inside Docker locally.

**Why use Docker just for the database?**

PostgreSQL must be installed somewhere to run. Your two options are:

- Install PostgreSQL directly on your Mac and manage it yourself
- Run it in a Docker container

The Docker approach is better because:

- Starting and stopping is one command (`docker-compose up -d` / `docker-compose down`)
- The database lives in an isolated container — it never conflicts with anything else on your machine
- Wiping the database for a clean start is one command (`docker-compose down -v`)
- Everyone on a team gets the exact same database version — no "works on my machine" issues

**What runs where during development:**

| Service | How it runs | Port |
| --- | --- | --- |
| PostgreSQL database | Docker container | `5432` |
| Spring Boot API | Directly on your Mac (via IntelliJ or `mvn spring-boot:run`) | `8080` |
| Angular frontend | Directly on your Mac (via `ng serve`) | `4200` |

Spring Boot connects to the Docker container the same way it would connect to any database — through `localhost:5432`. From Spring Boot's perspective, Docker is invisible.

## 4. Step 1 — Start the Database with Docker

### 4.1 Create docker-compose.yml

Create the file at `~/projects/levelup/docker-compose.yml` (the parent folder, not inside either project):

```yaml
version: '3.8'

services:
  postgres:
    image: postgres:16
    container_name: levelup_postgres
    environment:
      POSTGRES_DB: levelup_dev
      POSTGRES_USER: levelup
      POSTGRES_PASSWORD: levelup_dev_password
    ports:
      - "5432:5432"
    volumes:
      - levelup_postgres_data:/var/lib/postgresql/data

volumes:
  levelup_postgres_data:
```

### 4.2 Start Docker Desktop

Open Docker Desktop from your Applications folder. Wait for it to finish starting — you will see a green dot in the menu bar when it is ready.

### 4.3 Start the database

Open a terminal, navigate to `~/projects/levelup/`, then run:

```bash
docker-compose up -d
```

The first run downloads the PostgreSQL image (~300 MB). Subsequent starts are instant.

To verify it is running:

```bash
docker ps
```

You should see a row with `levelup_postgres` and status `Up`.

### 4.4 Database commands reference

```bash
# Start database (in background)
docker-compose up -d

# Stop database (data is preserved)
docker-compose down

# Wipe everything and start fresh (destroys all data)
docker-compose down -v

# View database logs
docker logs levelup_postgres
```

## 5. Step 2 — Set Up the Spring Boot Backend

### 5.1 Generate the project

Go to [start.spring.io](https://start.spring.io) and configure it:

| Setting | Value |
| --- | --- |
| Project | Maven |
| Language | Java |
| Spring Boot | Latest 3.x stable |
| Group | `com.levelup` |
| Artifact | `levelup-api` |
| Packaging | Jar |
| Java | 21 |

**Add these dependencies before generating:**

- Spring Web
- Spring Data JPA
- Spring Security
- PostgreSQL Driver
- Validation
- Lombok

Click **Generate**, unzip the download, and move the folder to `~/projects/levelup/levelup-api/`.

### 5.2 Open in IntelliJ

Open IntelliJ IDEA → **Open** → select the `levelup-api/` folder. IntelliJ detects the `pom.xml` and imports it as a Maven project. Wait for the initial indexing to complete.

### 5.3 Add remaining dependencies to pom.xml

Open `pom.xml` and add the following inside the `<dependencies>` block (in addition to what was generated):

```xml
<!-- JWT -->
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-api</artifactId>
    <version>0.12.6</version>
</dependency>
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-impl</artifactId>
    <version>0.12.6</version>
    <scope>runtime</scope>
</dependency>
<dependency>
    <groupId>io.jsonwebtoken</groupId>
    <artifactId>jjwt-jackson</artifactId>
    <version>0.12.6</version>
    <scope>runtime</scope>
</dependency>

<!-- WebClient for IGDB API calls -->
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-webflux</artifactId>
</dependency>

<!-- PostgreSQL array / JSONB support -->
<dependency>
    <groupId>io.hypersistence</groupId>
    <artifactId>hypersistence-utils-hibernate-63</artifactId>
    <version>3.7.3</version>
</dependency>

<!-- Flyway — schema migrations -->
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-core</artifactId>
</dependency>
<dependency>
    <groupId>org.flywaydb</groupId>
    <artifactId>flyway-database-postgresql</artifactId>
</dependency>

<!-- Security test support -->
<dependency>
    <groupId>org.springframework.security</groupId>
    <artifactId>spring-security-test</artifactId>
    <scope>test</scope>
</dependency>
```

After saving, IntelliJ will prompt you to reload Maven — click **Load Maven Changes**.

### 5.4 Configure application.properties

File location: `src/main/resources/application.properties`

Replace the generated content with:

```properties
spring.application.name=levelup-api
server.port=8080

spring.datasource.url=${DB_URL}
spring.datasource.username=${DB_USERNAME}
spring.datasource.password=${DB_PASSWORD}
spring.datasource.driver-class-name=org.postgresql.Driver

spring.jpa.hibernate.ddl-auto=validate
spring.jpa.show-sql=false
spring.jpa.properties.hibernate.dialect=org.hibernate.dialect.PostgreSQLDialect
spring.jpa.properties.hibernate.format_sql=true

jwt.secret=${JWT_SECRET}
jwt.access-token-expiration-ms=900000
jwt.refresh-token-expiration-ms=1209600000

igdb.client-id=${TWITCH_CLIENT_ID}
igdb.client-secret=${TWITCH_CLIENT_SECRET}
igdb.token-url=https://id.twitch.tv/oauth2/token
igdb.base-url=https://api.igdb.com/v4

spring.data.web.pageable.default-page-size=20
spring.data.web.pageable.max-page-size=50
spring.data.web.pageable.one-indexed-parameters=false

spring.profiles.active=${SPRING_PROFILES_ACTIVE:dev}
cors.allowed-origins=http://localhost:4200
```

### 5.5 Create application-dev.properties

File location: `src/main/resources/application-dev.properties`

> **Create this file manually.** It is not generated. Add it to `.gitignore` immediately — it contains secrets.

**Where these values come from — your Docker container:**

The three database values you put here come directly from what you defined in `docker-compose.yml`. Here is the mapping:

| docker-compose.yml | application-dev.properties | What it means |
| --- | --- | --- |
| `POSTGRES_DB: levelup_dev` | `DB_URL=jdbc:postgresql://localhost:5432/levelup_dev` | The database name goes at the end of the URL. The host is always `localhost` and port is `5432` because Docker maps the container's port to your Mac. |
| `POSTGRES_USER: levelup` | `DB_USERNAME=levelup` | Copied directly. |
| `POSTGRES_PASSWORD: levelup_dev_password` | `DB_PASSWORD=levelup_dev_password` | Copied directly. |

The URL format is always: `jdbc:postgresql://localhost:5432/<your_POSTGRES_DB_value>`

If you ever change a value in `docker-compose.yml` (e.g. rename the database or change the password), update this file to match, then run `docker-compose down -v && docker-compose up -d` to recreate the container with the new settings.

```properties
DB_URL=jdbc:postgresql://localhost:5432/levelup_dev
DB_USERNAME=levelup
DB_PASSWORD=levelup_dev_password

JWT_SECRET=dev_secret_key_replace_this_in_production_must_be_256_bits_long_aaaa

TWITCH_CLIENT_ID=your_twitch_client_id_here
TWITCH_CLIENT_SECRET=your_twitch_client_secret_here

spring.jpa.hibernate.ddl-auto=update
spring.jpa.show-sql=true
```

> **IGDB credentials:** You need a free Twitch developer account. Go to [dev.twitch.tv](https://dev.twitch.tv), create an application, and copy the Client ID and Client Secret into this file.

### 5.6 Add application-dev.properties to .gitignore

Open `.gitignore` in the project root and add:

```text
src/main/resources/application-dev.properties
```

### 5.7 Create the Flyway migration file

Flyway manages your database schema. It runs SQL migration files on startup in order, ensuring the schema matches your Java entities.

Create the directory: `src/main/resources/db/migration/`

Create the file: `src/main/resources/db/migration/V1__initial_schema.sql`

Leave it empty for now — you will fill it in as you build your entities. Every table you create needs a corresponding `CREATE TABLE` statement in this file. Future schema changes go in `V2__description.sql`, `V3__description.sql`, etc.

### 5.8 Run the backend

Make sure Docker is running and the database container is up (`docker ps`), then:

- In IntelliJ: click the green **Run** button next to `LevelUpApiApplication`
- Or in terminal: `cd ~/projects/levelup/levelup-api && mvn spring-boot:run`

You should see Spring Boot start up and connect to PostgreSQL. The log will say something like:

```text
Started LevelUpApiApplication in 3.2 seconds
```

If it fails with a database connection error, the Docker container is not running — run `docker-compose up -d` first.

## 6. Step 3 — Set Up the Angular Frontend

### 6.1 Generate the project

Open a terminal and run:

```bash
cd ~/projects/levelup

ng new levelup --standalone --routing --style=scss --no-ssr
```

This creates `~/projects/levelup/levelup/`.

### 6.2 Verify it runs

```bash
cd levelup
ng serve
```

Open `http://localhost:4200` in a browser. You should see the default Angular welcome page.

### 6.3 Set up environments

Angular needs to know where the API is. Create two files:

`src/environments/environment.ts`:

```typescript
export const environment = {
  production: false,
  apiUrl: '/api/v1',
};
```

`src/environments/environment.prod.ts`:

```typescript
export const environment = {
  production: true,
  apiUrl: 'https://your-railway-app.railway.app/api/v1',
};
```

> The dev `apiUrl` uses `/api/v1` (no `localhost:8080`) because the proxy config below rewrites it automatically.

### 6.4 Set up the dev proxy

Without this, your Angular app (port 4200) will get CORS errors when calling the Spring Boot API (port 8080).

Create `src/proxy.conf.json`:

```json
{
  "/api": {
    "target": "http://localhost:8080",
    "secure": false,
    "changeOrigin": true,
    "logLevel": "debug"
  }
}
```

Open `angular.json`. Find the `"serve"` section and add the proxy config:

```json
"serve": {
  "builder": "@angular-devkit/build-angular:dev-server",
  "options": {
    "proxyConfig": "src/proxy.conf.json"
  }
}
```

Now restart `ng serve`. All requests from Angular to `/api/...` will automatically forward to `http://localhost:8080/api/...`.

### 6.5 Build the core folder structure

Run these commands from inside `~/projects/levelup/levelup/`:

```bash
# Core guards
ng generate guard core/guards/auth --functional --skip-tests
ng generate guard core/guards/guest --functional --skip-tests
ng generate guard core/guards/onboarding --functional --skip-tests

# Core interceptors
ng generate interceptor core/interceptors/jwt --skip-tests
ng generate interceptor core/interceptors/error --skip-tests

# Core services (create one to start)
ng generate service core/services/auth --skip-tests
ng generate service core/services/user --skip-tests
```

Build features one at a time as you implement each phase of the roadmap — do not create all folders on day one.

## 7. Day-to-Day Startup Sequence

Every time you sit down to work on LevelUp, do this in order:

```text
1. Open Docker Desktop — wait for it to show green / ready
2. In terminal: cd ~/projects/levelup && docker-compose up -d
3. Run the Spring Boot backend (IntelliJ or mvn spring-boot:run)
4. In terminal: cd ~/projects/levelup/levelup && ng serve
5. Open http://localhost:4200 in browser
```

To shut down at the end of a session:

```text
1. Stop ng serve (Ctrl+C in terminal)
2. Stop Spring Boot (red square in IntelliJ, or Ctrl+C in terminal)
3. docker-compose down  (or just leave it running — it doesn't hurt anything)
```

## 9. Common Problems

**Spring Boot fails to start with "Connection refused" on port 5432**
The database is not running. Open Docker Desktop and check the container is up, or run `docker-compose up -d`.

**Spring Boot fails to start with "Schema-validation: missing table"**
Flyway ran but your migration SQL does not match your Java entities. Either the `V1__initial_schema.sql` file is missing your tables, or an entity was added without a migration. Add a new migration file.

**ng serve shows CORS errors in the browser console**
The proxy config is not wired in. Check that `proxyConfig: "src/proxy.conf.json"` is in `angular.json` under the `serve` options and restart `ng serve`.

**Docker command not found in terminal**
Docker Desktop is installed but its CLI tools are not in your PATH. Open Docker Desktop, go to Settings → Advanced, and make sure "Add Docker CLI to PATH" is enabled. Restart your terminal.

**Port 5432 already in use**
Something else (a native PostgreSQL install) is running on port 5432. Either stop that service or change the host port in `docker-compose.yml` from `"5432:5432"` to `"5433:5432"` and update `application-dev.properties` to use port `5433`.

**application-dev.properties not being picked up**
Spring Boot loads `application-dev.properties` when the active profile is `dev`. The `application.properties` file sets `spring.profiles.active=${SPRING_PROFILES_ACTIVE:dev}` which defaults to `dev` when the environment variable is not set. If you are running through IntelliJ, check that no `SPRING_PROFILES_ACTIVE` environment variable is set to something else in the run configuration.
